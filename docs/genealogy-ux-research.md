# Исследование UX/UI генеалогических сервисов (США, Россия, Европа)

## Цель
Сформировать требования к целевой HTML-странице семейного дерева с максимально комфортным UX/UI.

## Метод (мульти-агентный подход)
Мы разделили анализ на 4 «агента»:

1. **Агент «Рынок и паттерны»** — выявляет устойчивые UX-паттерны у лидеров рынка.
2. **Агент «Визуализация дерева»** — сравнивает типы представления дерева (Family/Pedigree/Fan/List).
3. **Агент «Данные и совместная работа»** — изучает работу с источниками, подсказками, импортом GEDCOM.
4. **Агент «Техническая архитектура страницы»** — проектирует целевую HTML-страницу, производительность и доступность.

## 1) Что показывают сервисы США

### FamilySearch (США)
Ключевые особенности, которые влияют на UX:
- Онбординг «в 3 шага» (добавь известных родственников → система ищет совпадения → дерево растёт).
- Модель **shared tree**: единый профиль умершего человека, чтобы не дробить данные в десятки копий.
- Сильный фокус на **collaboration**: родственники могут дополнять данные и источники.
- Приватность живых людей выделена явно (данные о living-персонах приватны).

UX-вывод: пользователь быстрее получает «вау-эффект» от автодостраивания, а не от пустого холста.

### Ancestry (США)
Ключевые особенности:
- Простой вход в сценарий «начни с того, что знаешь».
- Механика **Hints/подсказок** (листочки) как постоянный мотиватор продолжать.
- Насыщенная экосистема: записи, документы, ДНК, медиа.

UX-вывод: людям нужен не только граф дерева, но и постоянный поток релевантных next actions.

## 2) Что показывают сервисы Европы

### MyHeritage (Европа/глобально)
Ключевые UX-находки:
- Несколько режимов отображения: Family, Pedigree, List и Fan.
- **Fan View** даёт красивую визуализацию предков в «веере», поддерживает зум и смену корневой персоны.
- Цветовое кодирование ветвей повышает читаемость родственных линий.

UX-вывод: один режим отображения не покрывает все пользовательские задачи; нужны переключаемые представления.

### Geneanet (Европа, Франция)
Ключевые особенности:
- Чёткий флоу: создать дерево с нуля или импортировать GEDCOM.
- Подчёркивается переносимость данных и совместимость с другими системами.
- Есть настройка уровня приватности дерева.

UX-вывод: контроль над данными и интероперабельность (GEDCOM) — обязательны даже для «личной» страницы.

## 3) Что показывают сервисы России

### Familio (Россия)
Наблюдаемые особенности:
- Низкий порог входа: «создайте древо бесплатно».
- Простая карточка человека: ФИО, дата/место рождения, фото.
- Акцент на массовую доступность и популяризацию генеалогии.

UX-вывод: в русскоязычном сегменте особенно важны ясные тексты, простые формы и минимальная когнитивная нагрузка.

## 4) Итоговые UX/UI принципы для нашей страницы

1. **Мгновенная полезность**: пользователь добавляет 2–3 поколения и сразу видит красивое дерево.
2. **Режимы отображения**: минимум 2 режима на старте — Family (горизонтальный) и Fan (радиальный).
3. **Карточка персоны справа**: единая панель редактирования/просмотра без модальных «ловушек».
4. **Подсказки действий**: «добавить родителей», «добавить детей», «прикрепить источник/фото».
5. **Ясная приватность**: заметные бейджи «жив»/«умер», скрытие чувствительных полей по умолчанию.
6. **Интероперабельность**: импорт/экспорт GEDCOM и JSON.
7. **Доступность**: контраст, клавиатурная навигация, ARIA, адаптация под мобильные.
8. **Производительность**: виртуализация/ленивая отрисовка узлов для больших деревьев.

## 5) Проект целевой HTML-страницы

### 5.1 Информационная архитектура
- **Header**: название рода, поиск по людям, переключатель режима (Family/Fan), кнопки Import/Export.
- **Main Canvas**: интерактивное дерево (pan/zoom, drag).
- **Right Sidebar**: карточка выбранного человека.
- **Bottom Action Bar (mobile)**: Add Parent, Add Child, Add Spouse, Attach Source.

### 5.2 UX-сценарии первого запуска
1. Приветственный блок: «Начните с себя».
2. Мини-форма: имя, фамилия, год рождения.
3. Автосоздание базового графа (родители/дети placeholders).
4. Микро-тур по элементам интерфейса (до 4 шагов).

### 5.3 Компоненты UI
- **Person Node**:
  - имя, годы жизни, мини-аватар;
  - цвет ветви;
  - статус заполненности (например, 60%).
- **Relationship Edges**:
  - родитель-ребёнок;
  - супруги;
  - усыновление/опекунство отдельной визуальной линией.
- **Person Drawer**:
  - основные поля;
  - события (рождение, брак, смерть, переезды);
  - источники/медиа;
  - заметки.

### 5.4 Визуальный стиль
- Чистый светлый фон + мягкие акцентные цвета ветвей.
- Скруглённые карточки, лёгкие тени, аккуратная типографика.
- Плотность интерфейса: 2 режима (comfortable / compact).

### 5.5 Технический стек (для web-версии)
- **HTML5 + CSS variables + JS/TS**.
- Для дерева: D3.js или React Flow / Cytoscape.js (в зависимости от объёма интерактива).
- Хранение:
  - локально: IndexedDB + autosave;
  - опционально: backend API (PostgreSQL + object storage для фото/документов).
- Форматы:
  - внутренний JSON-модель;
  - импорт/экспорт GEDCOM.

### 5.6 Нефункциональные требования
- Время первого meaningful render: до 2 секунд на дереве ~200 персон.
- Навигация: 60 FPS при pan/zoom на средних ноутбуках.
- A11y: WCAG 2.2 AA.
- Локализация: RU/EN на уровне UI-строк и форматов дат.

## 6) Минимальный MVP (что делаем первым)
1. Family View с pan/zoom.
2. Добавление/редактирование персоны.
3. Связи родитель/ребёнок и супруги.
4. Поиск по имени и переход к персоне.
5. Экспорт/импорт JSON (GEDCOM — вторым этапом).

## 7) Phase 2
1. Fan View.
2. Источники, медиа-галерея.
3. Коллаборация (комментарии/приглашения).
4. «Подсказки заполнения» на основе неполных узлов.

---

## Финальная концепция
Наша страница должна сочетать:
- **простоту входа** (как у массовых сервисов),
- **красивые режимы визуализации** (как у продвинутых генеалогических платформ),
- **контроль данных и приватности** (как у профессиональных решений),
- и **быструю работу даже на больших деревьях**.

Итог: не просто «картинка дерева», а персональный центр семейной истории.
